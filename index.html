I · 🌰 Seed

Every forest starts with one file

git-forest is a pattern before it is a package. The kernel is a single index.js with no node_modules: read it in an afternoon, change it, fork it. npx is only a shortcut for the same thing.

  1. Copy

    Put index.js and .gitignore in an empty folder. That folder is your forest, and the kernel is yours to edit.

  2. Run

    Start it with node index.js. On first boot it sets up Git and the push-to-deploy hook, then listens on :3000.

  3. Grow

    Any folder with an index.js becomes a route and an isolated worker. Delete the folder and the tree is gone.

# 1 · copy the seed
mkdir my-forest && cd my-forest
curl -O https://raw.githubusercontent.com/davay42/git-forest/main/index.js
curl -O https://raw.githubusercontent.com/davay42/git-forest/main/.gitignore

# 2 · run it   (or: npx @davay/git-forest)
node index.js

# 3 · grow a tree
mkdir hello && cat > hello/index.js <<'EOF'
import { createServer } from 'node:http';

createServer((req, res) => res.end('🌲 hello from the forest'))
  .listen(process.env.SOCKET_PATH);   // listening on the socket = ready
EOF
# commit & push (see Graft): only this worker is swapped, nothing restarts

Requires Node.js ≥ 22 and Git. That is the entire toolchain: no framework, no database, no process manager, no CI.

IV · 🌳 Trees

A tree is a folder with an index.js

An autonomous agent with three obligations, and nothing else to learn.

1 · Membrane

The kernel strips the prefix: /poll/vote arrives as /vote. Use relative URLs and the folder can be renamed, moved or tunnelled.

2 · Lifecycle

Listen on SOCKET_PATH. The kernel senses readiness with backoff, swaps atomically, and keeps the old version if yours fails to boot.

3 · Teleology

Just write files. Components never run git; the kernel breathes changes into history on its own.

Mycelium

Every request carries x-forest-device-id, and x-forest-user-id when the device is linked in users.json. No lookups, no sessions.

// poll/index.js — a complete tree
import { createServer } from 'node:http';
import { appendFile, mkdir } from 'node:fs/promises';
import { join } from 'node:path';

const ROOT = join(process.env.COMPONENT_DIR, '..');

const server = createServer(async (req, res) => {
  const user = req.headers['x-forest-user-id'];          // from the mycelium
  if (!user) return res.writeHead(401).end('Please log in');

  const dir = join(ROOT, 'notes');
  await mkdir(dir, { recursive: true });
  await appendFile(join(dir, `${user}.md`), '\n## New entry\n');  // write to the soil
  res.end('Saved. <a href="./">back</a>');                     // relative paths!
});

server.listen(process.env.SOCKET_PATH);                      // listening = ready
process.on('SIGTERM', () => {
  server.close(() => process.exit(0));
  setTimeout(() => process.exit(0), 3000).unref();
});

Two strands: index.js is the behavioural strand, an optional index.md in MD-LD is the declarative strand. Either can be regenerated from the other, which is what makes a component a portable seed.

V · 🍄 Mycelium

A tree of folders. A graph of links. A forest of both.

Directories give you hierarchy: one parent, many children. Markdown-linked data adds the edges that cross it, the way fungal threads join separate trees underground. Trees plus shared soil plus links: that is a forest, and it needs no database to be one.

  • tree edge: a folder contains a file
  • graph edge: a ?predicate link written in Markdown
  • component (agent)
  • knowledge file

Illustrative layout. The folders are the hierarchy; the link edges live inside the Markdown files as annotations, so moving a folder never breaks the graph.

V · 🍄 Mycelium · the database

mdld-parse: the database is a folder of Markdown

No SQLite, no ORM, no server. MD-LD turns annotated Markdown into RDF quads and back, and mdld-parse.js is one zero-dependency file (about 24 KB gzipped). Copy it into public/ and every component can query the forest's knowledge with plain array methods.

<!-- catalog/espresso.md : a record and a graph at once -->
[cat] <tag:shop@example.org,2026:catalog/>

# Espresso {=cat:espresso .cat:Drink label}
[3.20] {cat:price ^^xsd:decimal}
Made from [Arabica beans] {+cat:arabica ?cat:uses label}.
Sold at [the counter] {+cat:counter ?cat:soldAt label}.
import { parse, merge, generate } from '../public/mdld-parse.js';
import { readFile, readdir } from 'node:fs/promises';
import { join } from 'node:path';

const dir = join(process.env.COMPONENT_DIR, '../catalog');
const files = (await readdir(dir)).filter(f => f.endsWith('.md'));
const docs = await Promise.all(files.map(f => readFile(join(dir, f), 'utf8')));

// many documents, one graph
const { quads } = merge(docs);

// ask it questions with plain array methods
const about = iri => quads.filter(q => q.subject.value === iri);
const uses = about('tag:shop@example.org,2026:catalog/espresso')
  .filter(q => q.predicate.value.endsWith('uses'))
  .map(q => q.object.value);

// write the graph back out as Markdown: a reviewable git diff
const { text } = generate({ quads });

Trees are graphs

A heading with {=iri} is a node. Nesting is the tree; ?predicate links are the extra edges that turn a tree into a forest.

Git is the history

Every edit to the graph is a text diff. merge() combines append-only documents, so branches and backups just work.

Round-trip safe

parse ↔ generate, plus render ↔ deconstruct for lossless HTML. A <quad-graph> element can draw any result as a force-directed graph.

VI · 🌬️ Breath

The forest tends itself

The kernel describes itself in index.md, written in MD-LD, in four acts. Each role declares its trigger, path, input, output, prerequisite and plan, so the documentation is also a graph you can parse.

I · Meeting the world

Decide where every incoming byte goes.

  • serve static
  • route to component
  • git HTTP backend
  • websocket upgrade

II · Knowing who and what

Device identity, device map, history.

  • process identity
  • watch device map
  • breathe git changes
  • introspect

III · Growing the forest

Discovery instead of deployment.

  • swap component
  • reload
  • ensure git hook
  • heal git state

IV · Breathing and resting

A rhythm no visitor triggers.

  • health
  • status
  • sync backup
  • graceful shutdown
5 sbreath: stage and commit changes
5 minquiet: sleep and consolidate
1 hquiet: deep sleep, repack objects

Commit messages are derived from paths alone: users/alice/payments.md becomes user alice payments, and users/index.js becomes deploy users. The forest does not crash. It exhales.

VIII · ✂️ Graft

Push to the forest

The server is the Git remote. A post-receive hook inspects the diff: component changes hot-swap just that worker; a change to the root index.js triggers a graceful container restart.

# push-to-deploy
git remote add forest https://user:GIT_SECRET@forest.example.com/git/
git push forest main

# pull data commits first
git pull --rebase forest main
# Dockerfile: one container, one volume on /app
FROM node:22-alpine
RUN apk add --no-cache git git-daemon curl
WORKDIR /opt/git-forest-seed
COPY index.js .
COPY .gitignore .
WORKDIR /app
EXPOSE 3000
ENTRYPOINT ["sh", "-c", "\
  if [ ! -f 'index.js' ]; then \
    cp /opt/git-forest-seed/* . 2>/dev/null || true; \
  fi; \
  exec node index.js"]
VariableDefaultPurpose
PORT3000HTTP port
GIT_SECRETnonePassword for push-to-deploy
AUTH_SECRETrandomHMAC key for device cookies
GIT_BACKUP_URLnoneRemote for periodic backup pushes
FOREST_BREATH_MS5000Commit interval

Security in brief: timing-safe secret checks, rate-limited Git auth, .git, .env and the kernel itself are never served, each component is its own process behind a Unix socket, and a crashing build keeps the previous version alive.

What we hold to be self-evident

  1. Software should be owned, not rented.
  2. Complexity should be earned, not imposed.
