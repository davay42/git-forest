The Epistemological Inversion

Modern software engineering suffers from the "Database Illusion" and "Platform Dependency." We rent infrastructure, configure abstractions, and deploy through pipelines we do not own. git-forest discards these metaphors. It is not a framework; it is a realignment of computational ontology.

  • JavaScript is the Subject (The Will): The continuous, persistent process holding logic, state transitions, and decision-making capacity.
  • HTML/CSS is the Phenomenon (The Projection): The ephemeral, disposable shape the agent takes to communicate with the human visual cortex.
  • HTTP is the Membrane: The strict, impermeable boundary of the component's sovereignty.
  • The Filesystem is the Noumenon (Shared Truth): The unabstracted reality. Code, state, and data occupy the exact same physical space, readable as plain text.
  • Git is the Teleology: The arrow of time, the append-only memory, and the decentralized engine of consensus.

How It Works: The Nine Layers

git-forest distills the entire web stack into nine irreducible primitives. No databases. No frameworks. No orchestration. Just Node.js, Git, and the filesystem.

1

The Membrane

HTTP routing via raw TCP proxy. No Express. No middleware. Just string matching and Unix sockets.

2

The Process Tree

Each component is a child process. Isolation via OS boundaries. Hot-swap on Git push. Zero-downtime deployment.

3

Identity (FIP)

Device-first authentication via HMAC-signed cookies. Users are constellations of devices. Recovery is peer-to-peer trust.

4

State (The Soil)

The filesystem is the database. MD-LD (Markdown + Linked Data) provides semantic structure. Every file is plain text, human-readable.

5

Time (Git)

Autonomic breathing commits changes every 5 seconds. Sleep consolidation during quiet periods. Deep sleep maintenance for optimization.

6

Coordination (The Mycelium)

IPC-based device mapping. Components never call each other over HTTP. The kernel maintains shared state in memory.

7

Security

Header stripping, timing-safe comparisons, path validation. No third-party services. Pure cryptographic paranoia.

8

Autonomy

Components can run as daemons. The kernel breathes, sleeps, and tends the forest without human intervention.

9

Deployment

Push-to-deploy via Git. The post-receive hook inspects diffs and triggers targeted reloads. No CI/CD pipeline needed.

Component Authoring

A component is any root-level directory containing an index.js. It is an autonomous agent—a tree in the forest.

import { createServer } from 'node:http'; import { appendFile } from 'node:fs/promises'; import { join } from 'node:path'; const COMPONENT_DIR = process.env.COMPONENT_DIR; const ROOT = join(COMPONENT_DIR, '..'); const server = createServer(async (req, res) => { // Read identity from the mycelium const userId = req.headers['x-forest-user-id']; if (!userId) { res.writeHead(401); return res.end('Authentication required'); } // Write to the soil (filesystem) await appendFile( join(ROOT, 'payments', 'users', `${userId}.md`), '\n## New entry\n' ); // That's it. The kernel breathes the change into Git. res.end('Saved.'); }); server.listen(process.env.SOCKET_PATH, () => { process.send('ready'); // Signal the kernel });

🌐 The Membrane

The kernel strips the component prefix. /payments/checkout arrives at your component as /checkout. Use relative paths in HTML.

⚡ Zero-Downtime

Signal readiness via process.send('ready'). The kernel hot-swaps sockets. If your code crashes on boot, the old version stays live.

📝 Just Write Files

No Git commands. No commit requests. The kernel breathes automatically. Your component is a pure filesystem operator.

Identity Protocol (FIP)

Modern identity is a centralized ledger of PII. git-forest treats identity as a cryptographic proof of device continuity.

🔐 Device-First

The kernel issues an HttpOnly cookie containing a signed deviceId. No email. No password. Just math.

🌳 Users as Constellations

A user owns a set of devices. Any device can generate recovery links for new devices. No third-party auth service needed.

🍄 The Mycelium

The kernel maintains an in-memory map of deviceId → userId, fed by the /user component via IPC. Zero HTTP overhead.

The Forest Ontology

Every byte in a git-forest belongs to one of three substances. The .gitignore file is not a cleanup list; it is a declarative policy schema that defines the boundary between them.

📝 Code

The context. Logic that transforms inputs. Versioned. Example: index.js, public/styles.css

🌱 Knowledge

Data given context. Semantic, auditable. Versioned. Example: catalog/items.md, users/*/profile.md

🍂 Soil

Raw accumulation. The nutrients. Ephemeral. Example: sessions/, cache/

The Rule: Anything not in .gitignore is committed to Git. Anything in .gitignore is sovereign to the local container. The core flow is photosynthesis: components absorb raw data (Soil), apply logic (Code), and elevate it into auditable history (Knowledge).
